## 1. 什么是 OPC

OPC (One Person Company)，一人公司，听起来好像也不是什么新鲜词，毕竟单干的、自由职业的、独立开发者一直都有，每个时代都不缺这种人。

但今天我们说的 OPC，跟以前的"个体户"其实不太一样。

我自己的感受是，它其实是 AI 时代催生出来的新东西。

## 2. 为什么是现在

云这件事其实很多年前就成熟了。

服务器、负载均衡、TLS、CDN、对象存储、数据库，这些过去要专门请一个 SRE 团队维护的东西，现在点几下就能开通，还便宜。

但光有云其实不够，因为一个人除了写代码，还要做设计、写文案、回邮件、跑增长、看数据。

这些事一个人全揽下来，再有云加持，也是会累到崩溃的。

真正让 OPC 变得现实的，其实是 AI。

* 写代码有 Codex、Claude Code，一个人的工程产能能放大到接近一个小团队。
* 做设计有 v0、Lovable、Figma AI，懂审美比会画图更重要了。
* 写文案、邮件、SEO 描述这种事，AI 能给你 80% 的初稿。常见的客服问题，一个 chatbot 也能挡掉大部分。
* 数据分析以前要写一堆 SQL，现在自然语言问一下就行。

云解决了"东西在哪儿跑"，AI 解决了"东西谁来做"，两件事一起被外包出去之后，一个人撑起一家公司就不再是什么传奇故事了。

国外这两年也确实出现了不少这样的例子：Sahil Lavingia 用一支极小的远程团队，让 Gumroad 持续盈利了很多年，Pieter Levels 一个人独立开发并运营了好几款产品，加在一起年收入有几百万美金。

还有越来越多的独立开发者，一个 Twitter 账号 + 一个 Stripe 账号 + 一个 Vercel 项目，做出了过去要 A 轮融资才能撑起来的东西。

## 3. 以 codepie 为例

下面想以我自己最近在做的 codepie （codepie.roseduan.cn）为例，讲讲一个人是怎么把这件事跑起来的。

codepie 是一个我独自运营的在线课程平台，目前所有的事情都是我一个人在做：写代码、做设计、跑营销、回用户消息。

![](/img/wechat/62-opc-build-product/01.png)

下面就从技术选型和成本两个方面来聊一下。

### 技术选型

我选技术其实没什么花哨的标准，就一条：能干活的前提下，挑维护成本最低、心智负担最小、上限又不会被锁死的那个。

#### 前端

前端用的是 `Next.js 16 + React 19 + TypeScript`。一个框架把路由、SSR、SEO、API、中间件全包了。

课程详情页要 SEO，付费校验要后端逻辑，App Router 把这两件事统一在一棵树里，挺省心。

样式直接用 `Tailwind CSS`，没有上任何组件库。

一个人维护 UI，最怕的就是组件库版本一升级把样式打乱，原子化 class 让样式归属于页面本身，比较稳。

#### 数据库

主数据库主要靠 `Supabase`，Postgres + Auth + Storage 一起搞定。

我不需要自己搭 OAuth、不需要管数据库备份、不需要写注册登录页。

用户、订单、解锁状态几张表就解决了。

限流和缓存用了 `Upstash Redis`，serverless 形态，按请求计费，闲的时候几乎不花钱。

登录用 `NextAuth v5`，跟 Supabase 配合处理 GitHub / Google 登录。

#### 部署 / 运维

部署直接用 `Vercel`，git push 上去就部署完了，预览环境、TLS、CDN 都自带。

数据看 `Vercel Analytics` 和 `Speed Insights` 的免费版，前期足够用。

域名在 `Cloudflare` 注册的，一年 80 块左右。

#### 开发工具

日常开发我用 Claude Code 和 Codex 比较多，重构、调试、SQL 调优都靠它们。

CI 用 GitHub Actions 跑测试，保证主分支随时可以发布。

整套技术栈背后的想法很简单：把所有非核心的事情都交给云，自己只写"只有我能写"的那部分。

### 成本

成本其实是这件事里最让我意外的一部分，下面是上线 codepie 产品的大致成本：

| 项目 | 月成本 | 说明 |
| --- | --- | --- |
| Vercel | $0 | Hobby 免费版，前期流量够用 |
| Supabase | $0 | Free 计划，500MB 数据库 + 1GB 存储 |
| Upstash Redis | $0 | 免费 10000 请求/天 |
| 域名 | ≈ ¥7 / 月 | Cloudflare，一年 ¥80 |
| Claude / Codex 订阅 | $20 | 核心生产力工具 |
| 邮件服务 (Resend) | $0 | 免费 3000 封/月 |
| 其他（图床、监控） | $0 | Vercel 自带或 Supabase Storage |
| 合计 | ≈ $27 / 月 |  |

只有等 DAU 真的涨起来之后，Vercel 和 Supabase 才会跨过免费门槛。

到那时候，Vercel Pro 月、25/月，加起来也就 $80 不到，而那个时候产品大概率已经能自己养活自己了。

对比一下传统创业，买服务器、雇前后端 + 设计、买协作软件，一个月烧几万块是很正常的。

几万块跟两百块，差的其实不只是钱，而是试错的次数，几万块烧错了你要痛三个月，两百块烧错了下个礼拜你又能开一个新项目。

## 4. 几点经验

上线一个产品，有几个当初没多想、回头看挺重要的决定，也算是一点感悟吧。

* 不上"大而全"的东西。不上 Strapi，不上自部署的 Prisma + PG，不上 Kubernetes。每多一个组件，都是一份维护成本，一份心智负担。
* 内容比 UI 重要。UI 越无聊越好，把时间花在产品本身的内容和体验上，比花在做酷炫首页和复杂动效上回报高 10 倍。用户不会因为你的 hover 动画就掏钱。
* 早一点上线，晚一点优化。免费部分早早放出去收反馈，比闭门 3 个月做完美再发布要强。前者让你知道方向对不对，后者只是让你的代码看起来更"漂亮"一点。
* AI 是放大器，不是替代品。AI 替不了你的判断和品味，但能把你的判断翻倍交付。把它用在重复劳动上，重构、对齐、写测试、调样式，然后把判断力留给真正要紧的事。
* 不要拒绝免费 tier。很多独立开发者觉得"免费的不专业"，但其实 Vercel / Supabase / Upstash 的免费额度足够撑到产品验证完成。在没有验证之前付钱，纯属浪费。

## 5. 写在最后

折腾下来最大的感受是，OPC 这件事的本质，其实是杠杆的换挡。

以前做产品要钱，要服务器、要团队、要授权；现在做产品要的是判断力，在一堆云服务、AI 工具、开源框架里挑出几个"够用又不绑架你"的组合，剩下的精力压在内容和用户体验上就行。

codepie 现在每月不到 $30 的成本就能稳定跑着，一个人能干完过去十几个人才能干的事。

这件事本身比产品还让我兴奋，它意味着，任何一个有手艺、有判断的人，今天都可以把自己的能力直接做成产品交到用户手里，不需要谁来许可你。

AI 时代真正的红利，可能不是"AI 替你做了什么"，而是"AI 让一个人能做什么"。

前者是工具，后者才是杠杆。

如果你也在想"要不要试试做点什么"，结论其实挺简单的，现在的门槛已经低到没有什么借口了，剩下的就是动不动手而已。
